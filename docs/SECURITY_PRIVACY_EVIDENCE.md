# Security and Privacy Evidence

This record describes the controls implemented in the project and the verification evidence available as of 2026-08-27. It does not claim formal security certification, HIPAA compliance, or clinical-system authorization.

| Control | Implementation evidence | Verification evidence |
|---|---|---|
| Raw scan retention boundary | `scan_records` stores metadata JSON, not raw scan bytes. The storage registration procedure accepts only derived Mode A report and Grad-CAM artifact types; unavailable Mode B masks and geometry are rejected. | Schema review and typed artifact-registration tests passed. |
| Account isolation | Scan list, result persistence, artifact registration, artifact download, and deletion routes use authenticated procedures and scope records by `ctx.user.id`. | Unit tests verify that an out-of-scope artifact never calls the URL signer and an unowned scan triggers no metadata deletion. |
| Destructive-action protection | Delete-all accepts only the literal `DELETE_ALL_RESEARCH_HISTORY`; the UI requires the phrase before enabling the control. | Server validation test and UI implementation reviewed. |
| Artifact boundary | The unauthenticated generic `/manus-storage/*` proxy is removed. History lists artifact IDs/type only; a fresh signed URL is issued solely by the ownership-scoped download procedure. Raw upload files are not sent through the artifact procedure. | Ownership/download tests and local production startup verification passed. |
| Derived-artifact lifecycle | Registration uses deterministic owner/scan/type keys so retries overwrite the same slot instead of creating pending claims or new orphan keys. Per-scan and delete-all operations validate the owner namespace and physically delete each derived object before metadata; a storage failure preserves metadata for retry. | Eight focused lifecycle tests pass. The provider delete endpoint still requires an exact-head non-production integration check before a public physical-erasure claim. See `MANUAL_GATES.md`. |
| CSRF boundary | Cookie-authenticated tRPC mutations require a matching same-origin `Origin` header; cross-site or missing-origin cookie mutations fail closed. | Four focused regression tests cover same-origin, cross-origin, missing-origin, safe-method, and non-cookie paths. |
| Request correlation | FastAPI accepts only bounded safe request IDs and replaces malformed/oversized values with a generated UUID. | FastAPI test verifies valid propagation and oversized-ID replacement. |
| Public-demo abuse boundary | Inference, segmentation, analysis, and report requests have a 20-request-per-minute process-local burst limit with `429` and `Retry-After` responses. Keys use endpoint path plus the framework-provided `request.client.host`; the code deliberately does not trust caller-supplied forwarding headers. Expired client keys are pruned and concurrently tracked keys are capped at 2,048. | Unit and FastAPI integration tests verify bounded burst, correlation headers, key expiry, and key-cap behavior. Reverse-proxy client-address semantics are not independently verified, and this is not a distributed rate limiter; see `MANUAL_GATES.md`. |
| Upload safeguards | Browser Mode A upload requires a data-use acknowledgement and checks extension, MIME, size, pixels, image signature/decode, and channel mode. FastAPI additionally rejects obvious chromatic, blank, low-structure, non-dark-border, undersized, and over-4-megapixel inputs before inference; Grad-CAM output is capped at 512 pixels. Mode B endpoints fail closed before application-level file reads. | Regression tests prove obvious incompatible images do not reach inference. The heuristic is not a trained MRI-modality/OOD detector and cannot establish medical compatibility. |
| Scope and decision safeguards | Persistent academic disclaimer, Grad-CAM boundary, Mode B unavailable state, and safe chatbot refusal paths are implemented. | Desktop/mobile visual checks and FastAPI/chat tests passed. |
| Optional explanation-provider boundary | The provider is selected only by server-side `AI_PROVIDER`; a selected provider requires its own key and model and never cross-switches to the other provider. Raw OpenAI Responses and Gemini Interactions parsers accept only the documented completed model-text paths, and both request payloads carry `store: false`. Missing/invalid configuration, timeouts, malformed JSON, and safety-contract violations return the deterministic offline FAQ. | Provider-mocked FastAPI tests exercise realistic OpenAI/Gemini REST structures, disabled configuration, timeout, malformed/unsafe response, stateless payload settings, and refusal-before-provider-call paths. No live provider call is part of CI. |
| Assistant data minimisation | Browser and server allowlist only a bounded question and derived research fields. They omit raw MRI/DICOM/NIfTI bytes, previews, Grad-CAM binary/base64, filename, scan ID, account/user ID, email, signed URL, storage key, auth/session token, secret, and the full analysis object. Logs contain only provider, outcome, category, latency, and bounded request ID. | Client transport regression serializes the exact allowlist; backend provider-mock regression examines the structured provider payload. |
| Report integrity | The public report endpoint accepts only a short-lived HMAC-authenticated receipt issued for a complete Mode A EXP-005 result and a matching Grad-CAM SHA-256. It reconstructs report data from receipt claims, rejects client-supplied analysis fields, and fails closed when no server-only secret is configured. | Unit/API tests cover valid, tampered, expired, wrong-secret, missing-secret, Grad-CAM substitution, Mode B/unreportable issuance, extra analysis field, and process-local replay paths. The replay guard is explicitly not distributed protection or non-repudiation. |
| Artifact download integrity | EXP-005 artifact retrieval validates the original and final redirect URL as HTTPS, applies an optional owner-configured hostname allowlist, validates SHA-256 configuration before network I/O, enforces per-artifact declared/streamed byte limits, cleans partial files, and validates expected ONNX names/shapes at startup. | Tests cover invalid digest, disallowed original host, HTTPS-to-HTTP redirect, disallowed redirect host, declared/streamed oversize, truncated response, checksum mismatch, valid cache, and fixed 160×160 I/O contract checks. |

The remaining operational research risk is any future model change or Mode B activation. Every new artifact and hosting path requires security review before promotion. The live Mode A service remains limited to the verified experimental academic scope in `docs/CAPABILITY_MANIFEST.md`.
