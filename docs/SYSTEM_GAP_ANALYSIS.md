# System Gap Analysis

**Assessment scope:** NeuroInsight AI PR #1, `feature/overnight-safe-improvements`, assessed on 2026-08-23. This is an engineering and research-readiness record, not a clinical, legal, privacy-certification, or regulatory assessment.

## Verified system state

| Area | Verified status | Evidence and boundary |
|---|---|---|
| Public dashboard | Live academic demonstration | The dashboard is publicly available, with a permanent non-diagnostic notice and English/Hindi research copy. [1] |
| Mode A classifier | Available | EXP-005 provides experimental four-class 2D inference, validation-only calibration, abstention, real Grad-CAM, and PDF reporting. Its reported performance is fixed-split image-level only. [2] |
| Mode B segmentation | Unavailable by design | No full-volume model, case-disjoint held-out evaluation, calibrated uncertainty policy, or release decision exists. No masks, volume, measurements, or 3D output are shown as real outputs. [3] |
| Upload and derived artifacts | Available with constraints | Original MRI uploads are not stored by default. Consented derived report/Grad-CAM artifacts are ownership-scoped and retrieved through freshly issued signed URLs. [4] |
| History deletion | Metadata lifecycle implemented | Per-record and delete-all actions delete only the authenticated user’s artifact and scan metadata. The supplied storage abstraction has no physical object-delete endpoint; unreferenced derived objects become unreachable through the application. [4] |
| Deployment | Partial platform deployment | The dashboard and separate inference service are verified. This is not a claim that every research, storage, or full-volume worker component is production deployed. [5] |

## Defects addressed in this pull request

| Finding | Corrective action | Verification evidence |
|---|---|---|
| GitHub Actions failed before tests because pnpm was declared both in the workflow and `packageManager`. | Removed the duplicate action version and used the exact `packageManager` declaration as the version source. Moved supported pnpm settings into `pnpm-workspace.yaml` and refreshed the lockfile. | A subsequent PR workflow reached and passed all CI stages after the follow-on report fixture repair. [6] |
| A unit test depended on an externally injected inference URL and failed in CI when the URL was intentionally absent. | Replaced it with a deterministic fail-closed unit test. Added an explicit opt-in external health smoke command requiring `INFERENCE_API_BASE_URL`. | `pnpm test` verifies local no-submit behavior; the external check stays separate so CI does not pretend an unconfigured service is healthy. [6] |
| PDF test supplied a truncated hard-coded PNG and caused a report endpoint 500 in CI. | Replaced it with a valid in-memory PNG fixture generated by Pillow. | Backend suite passes the report-scope test with real image bytes. [6] |
| Python bytecode was tracked in the repository. | Removed tracked caches; expanded `.gitignore` and a CI hygiene guard for generated caches, local secrets, raw imaging data, and local checkpoints. | The guard is included in CI and verified locally against tracked files. [6] |
| Browser/server controls had no focused regression coverage for fresh signed downloads and cross-user deletion denial. | Extracted ownership-gated download and metadata-lifecycle logic into tested helpers. | Unit tests deny signing/deletion outside ownership, issue a fresh URL after a scoped lookup, and preserve deletion order. [4] |
| An authenticated API client could previously submit a Mode B scan record or segmentation/3D artifact despite the unavailable public capability. | Added server-side fail-closed rejection for Mode B persistence and artifact registration. | Direct validation tests show that valid Mode A persistence remains available while Mode B inputs are rejected. [6] |
| The public report endpoint could previously accept a segmentation analysis payload and synthetic mask overlay although Mode B is unavailable. | Restricted report generation to Mode A classification analysis and rejected segmentation report requests. | FastAPI regression tests confirm Mode A PDF generation and unavailable Mode B report refusal. [6] |
| Inference uploads lacked early byte, pixel-budget, decoder-warning, and incompatible-channel protections. | Added bounded upload reads, content-length rejection, a 12-megapixel limit, decompression-bomb escalation, and explicit mode validation; added matching browser-side preflight feedback. | FastAPI and web regression tests cover oversized, unsafe, unsupported, and valid input paths. [6] |
| The production dependency audit contained critical and high findings in direct and unused runtime dependencies. | Updated direct runtime dependencies, removed two unreachable prebuilt UI wrappers, and refreshed the lockfile. | `pnpm audit --prod --audit-level=high` reports no known vulnerabilities; full type, test, and build validation is run after the changes. [6] |

## Remaining non-automatic gates

| Area | Why it remains open | Required owner or research action |
|---|---|---|
| Full-volume segmentation | Existing 2D smoke work and BRISC 2D release do not establish full-volume evidence. | Obtain lawfully permitted full-volume data with provenance-backed case IDs, approved compute, then complete pre-specified case-disjoint train/validation/held-out evaluation. [3] |
| Model replacement | EXP-006 did not improve on EXP-005 and is not a promotion candidate. | Only a reproducible experiment that improves validation and untouched test evidence without weakening calibration, runtime, or provenance may be considered through a separate owner-approved release review. [2] |
| External technical supervision | The optional external service returned HTTP 429 before any recommendation. | Restore the owner-controlled quota, then send the prepared privacy-safe review packet and locally verify any recommendation. [7] |
| Repository branch protection | Templates and recommendations can be committed, but only repository owners can require reviewers/checks or enable private reporting. | Configure the recommended GitHub settings in `docs/REPOSITORY_GOVERNANCE.md`. |
| Production infrastructure | No paid resource, DNS, secret, or legal action is performed by this PR. | Use `docs/MORNING_SETUP_CHECKLIST.md` and `docs/DEPLOYMENT.md` for owner-managed deployment, secrets, rollback, and provider choices. [5] |

## Readiness conclusion

NeuroInsight AI is suitable for an **academic presentation**, **recruiter portfolio**, and **transparent research demonstration**. It is not ready for clinical use, diagnostic use, patient-specific decision-making, or a production medical deployment. A future pilot would require a separate governance, data, validation, security, and operational assessment; the current repository intentionally does not claim that bar.
