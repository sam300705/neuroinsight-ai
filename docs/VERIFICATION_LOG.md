## 2026-09-04 — Phase 2/3 continuation: proxy-aware rate limiting

The public FastAPI middleware previously keyed rate limits only from the immediate ASGI socket peer. On a serverless deployment, multiple unrelated visitors can share that platform-facing peer and therefore one process-local or Redis-backed bucket. The corrected boundary uses the first valid IP in `x-forwarded-for` only when the runtime declares the platform-owned `VERCEL=1` marker. [Vercel documents](https://vercel.com/docs/headers/request-headers) that standard deployments overwrite this header instead of forwarding an external caller's value, preventing spoofing at that boundary. Local and other deployments ignore the header; missing, empty, malformed, host-plus-port, and non-IP values fall back to the socket peer. The identity remains absent from application logs and is SHA-256 hashed before distributed key construction.
